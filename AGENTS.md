## Задача коротко

Open-set Vehicle ReID. На входе полный кадр 1920×1080 и BBox машины. Модель строит эмбеддинг, решение ищет совпадения в статической gallery и сохраняет три файла:
- `submission.csv` — top-10 кандидатов для каждого query;
- `embeddings.npy` — эмбеддинги всех объектов;
- `candidates.csv` — принятый кандидат с confidence либо отказ.

Как считаются баллы:

| Критерий | Вес | Что важно |
|---|---|---|
| Точность, mAP@10 по `submission.csv` | 45% | Junk выбрасывается до обрезки до 10 позиций, десятка не восполняется |
| Скорость на RTX A5000 | 20% | Полный балл: задержка ≤ 40 мс при batch=1 и ≥ 100 FPS. **В таймер входят чтение с диска и декодирование JPEG** |
| Инженерия | 15% | Docker офлайн одной командой, воспроизводимость, README |
| Режим кандидатов | 10% | 0.7·F1 + 0.3·TNR; в закрытом тесте около 20% query без пары |
| Защита | 10% | Обоснование, разбор ошибок, порог |

## Жёсткие правила

Нарушение любого пункта означает дисквалификацию всей команды.

1. **Каждый query обрабатывается независимо.** Для ответа на query доступны только сам этот query и вся статическая gallery. Запрещено:
   - использовать эмбеддинги, статистики или результаты других test-query;
   - query expansion, включая вариант «только по gallery»: он отдельно не разрешён;
   - кластеризовать test-query;
   - нормализовать по батчу query.

   Батчевый прогон разрешён, только если ответ на query не зависит от состава батча. Разрешены: TTA одного изображения, re-ranking внутри top-K gallery-кандидатов одного query (в том числе k-reciprocal), предвычисленные сходства gallery–gallery.
2. **`camera_id` можно использовать только для** PK-sampling, построения фолдов и junk-фильтра в локальной оценке. Ни сам `camera_id`, ни признаки на его основе не подаются в модель и не используются на инференсе.
3. **Номерные знаки.** Запрещено использовать остаточные признаки номера, включая артефакты размытия. Жюри делает контрольный прогон с залитой номерной зоной, и модель должна его пережить.
4. **Тестовые данные** (`test_query.csv`, `test_gallery.csv` и их картинки) не используются для обучения, подбора гиперпараметров и порога, ручной разметки или анализа ошибок. С ними можно только прогонять пайплайн и делать smoke-проверку формата.
5. **Внешние веса и датасеты** — только публичные и проверяемые. Для каждого ресурса в README записываются URL, автор, версия или тег, для весов ещё sha256. Ссылки на `latest` запрещены.
6. **Инференс полностью офлайн.** Интернет есть только на `docker build`, всё нужное для запуска лежит внутри образа.
7. **Версии пакетов фиксируются точно** (`==`).
8. **Все веса инференса вместе — не больше 2 ГБ.** Считаются файлы `.pt .pth .bin .onnx .engine .plan .safetensors .ckpt .trt .pb .tflite .npz` в каталоге решения.
9. **Результаты получает только код.** Никаких ручных правок `submission.csv` и `candidates.csv`.

Если задача требует нарушить правило или ты не уверен — остановись и спроси человека. Серые зоны и принятые по ним решения перечислены в [DECISIONS.md](DECISIONS.md).

## Треки и зоны владения

В команде два человека, у каждого свои агенты.

| Трек | Отвечает за | Пути |
|---|---|---|
| **A — модель** | Картинка → эмбеддинг: фолды, оценка, обучение, предобучение, маскирование номеров, TTA | `reid/data/`, `reid/model/`, `reid/eval/eval_local.py`, `configs/`, `splits/`, `scripts/train*.py`, `scripts/make_folds.py` |
| **B — инференс и продукт** | Декодирование, скорость, Docker, эмбеддинги → три файла: поиск, двойники, re-ranking, confidence, порог; README | `reid/infer/`, `reid/post/`, `reid/eval/validate_outputs.py`, `Dockerfile`, `docker-compose.yml`, `Makefile`, `scripts/bench*.py`, `scripts/setup_server.sh`, `README.md` |
| Общее | Меняется только с согласия обоих людей | `docs/contracts.md`, `reid/data/preprocess.py`, `AGENTS.md` |

Трек задачи виден по её ID в PLAN.md: `A…` или `B…`. Не правь чужую зону без явной просьбы, оставь заметку в PLAN.md.

## Как работать

- **Одна задача — одна ветка** (`a/<кратко>` или `b/<кратко>`) и один git worktree. В `main` вливать только после `make check`: валидатор формата, pytest и сквозной прогон на 50 картинках. `make check` появится в Д1 (задача B1.2), до этого запускай pytest и валидатор вручную.
- **Скрипты запускаются из корня репозитория с `PYTHONPATH=.`**, например `PYTHONPATH=. python scripts/eval_dumps.py --emb ...`. Окружение трека A описано в `requirements-train.txt`. Готовые модели и эмбеддинги в git не лежат; как их получить — в [docs/contracts.md](docs/contracts.md), раздел «Где взять артефакты».
- **Метрики — только через `reid/eval/eval_local.py`** на фолдах из `splits/`. Число без команды воспроизведения не считается.
- **Каждый эксперимент — строка в [EXPERIMENTS.md](EXPERIMENTS.md).** Решение, меняющее план, контракт или правила, — запись в [DECISIONS.md](DECISIONS.md).
- **Готовую задачу отмечай в PLAN.md:** `[x]`, хеш коммита, одна строка результата.
- **Проверки здравого смысла:**
  - случайные эмбеддинги должны давать mAP@10 около 0;
  - mAP@10 выше 0,98 на валидации — ищи утечку;
  - если прирост получен на одном фолде, а заявлен как общий, его нужно подтвердить.
- **Главная ловушка данных — «двойники».** У каждого test-query в gallery ровно один кадр той же машины с той же камеры (подробности в [docs/findings.md](docs/findings.md)). Это junk: любая модель поставит его первым. Логика поиска, confidence и оценки должна это учитывать.
- **Не выдумывай результаты.** Если что-то не запустилось или не проверено, так и напиши.

## GPU и деньги

Бюджет — 20–30 тыс. ₽ на всё. Подробности в [docs/infra.md](docs/infra.md).

- Оплата посекундная. **Выключенный сервер всё равно платит за GPU.** Экономят только пауза (shelve) и удаление.
- Не оставляй GPU простаивать. Вечером поставь ночную очередь экспериментов или скажи человеку, что сервер можно ставить на паузу.
- Долгие задачи запускай в `tmux`/`nohup` с логом в `logs/`. Чекпоинты копируй с сервера.
- Разработка идёт на 4090 (SM89) и A10 (SM86), стенд жюри — A5000 (SM86). **Не отправляй в сдачу TensorRT-движки, собранные не на SM86.** Скорость, измеренная на 4090, не равна скорости на стенде, смотри [docs/speed_table.md](docs/speed_table.md).
