Трек B принимает опубликованную пятифолдовую оценку трека A; обучение и замеры

## Принятая политика

1. L2-нормированные эмбеддинги → косинусный top-10. Равенство разрешается порядком gallery CSV.
2. Фильтра двойников нет. В `submission.csv` junk удаляет evaluator; в режиме
   кандидатов кадр той же машины с той же камеры является правильным ответом
   при наличии пары (D-023/D-024).
3. `verifier_final`, DINOv2 ViT-S/14, вход 168, переупорядочивает только исходный
   top-10: `cosine + 0.2 * sigmoid(logit)`. Добавлять кандидатов и использовать
   другие query запрещено. Политика реализована в `reid/post/verifier.py`.
4. Confidence — косинус кандидата, реально поднятого на первое место, а не
   смешанный score и не исходный максимум косинуса. Отказ при confidence < 0.583.
5. Flip-TTA выключен по D-044. Ансамбль из A-042 не входит в принятый релиз:
   подтверждения на пяти фолдах и замера скорости ещё нет.

## На чём основано решение

| Эксперимент | Свидетельство | Вывод |
|---|---|---|
| A-010, D-024 | k-reciprocal ухудшил оценку; идеальный фильтр двойников дал лишь +0.0007 mAP@10 | Обычный поиск, без этих двух модификаций |
| A-031 | Пять отдельных OOF-пар «эмбеддер + verifier»: 0.8068 / 0.7643 / 0.7809 / 0.7740 / 0.7932 | Верификатор улучшает оценку примерно на 0.018 |
| A-028 | Порог 0.5833; CandScore 0.9588 ± 0.0056, устойчивая область 0.550–0.633 | Используем 0.583 согласно D-044 и файлам сдачи |
| A-036 | Порог по выбранному после verifier кандидату: 0.9608 против 0.9607, оптимальные пороги совпадают | Шкалу cosine confidence сохраняем |
| A-038/A-039, D-045 | ViT-B и 12000 шагов не улучшили результат по сравнению с ViT-S/168/3000 | Самая лёгкая подтверждённая конфигурация |

Числа взяты из `EXPERIMENTS.md` на коммите `f58fe7e`. У A-031 сводное число
0.7838, а среднее пяти напечатанных значений — 0.78364. До получения машинного
отчёта указываем **≈0.784**, не объединяем эту строку с более поздними
агрегатами 0.787 из `docs/defense_notes.md`: происхождение их различия пока
не установлено. Это не новая метрика и не анализ test.

## Инженерная проверка

`make check PYTHON=.venv/bin/python` проверяет стабильный порядок при равных
score, независимость reranking для каждого query, применение порога,
формат трёх выходов и сквозной прогон на 50 кадрах. В `reid/infer/` и
`reid/post/` нет входного поля camera_id и фильтрации по нему.

Повтор оценки допустим только на `splits/fold{k}_query.csv` и
`splits/fold{k}_gallery.csv`, с эмбеддером и verifier, обученными **без** k.
`final_all_data` и `verifier_final` для такой оценки использовать нельзя:
они обучены на всех пяти фолдах. Все метрики считает `reid/eval/eval_local.py`.

Дальнейшая смена поиска или моделей требует нового решения и OOF-подтверждения.
