# Предложение актуализации contracts — НЕ ПРИНЯТЫЙ КОНТРАКТ

Дата 27.09.2026, код `479ecd7`. `docs/contracts.md` не изменялся: по AGENTS
требуется согласие обоих людей и запись в DECISIONS. Ниже предлагается описать
уже реализованное, без новых моделей, изменения правил или разрешения серых зон.

## C3/C4: legacy и fusion раздельно

- Указать D-051: рабочий Extractor использует `model.features()` / pooling + L2
  **без BNNeck**, как C4; обучающий `forward()` может быть другим API.
- Дополнить список pooling фактическими `cls_top16`/`top16`, не сводить их к avg.
- Для fusion отдельный `fusion_config.json`: компоненты, фиксированные
  `similarity_std` и происхождение train-fold/gallery данных. Истинная D — сумма
  D компонентов; конкатенация с коэффициентами, пропорциональными
  `1/sqrt(similarity_std)`, затем L2. Конфиги/веса/manifest имеют SHA.
- C4 обязан однозначно связывать каждый OOF dump с checkpoint/YAML, fold,
  preprocessing, pooling и dtype. Идентичное имя backbone не доказывает
  одинаковость full_avg/top16 или FP32/FP16 представлений.
- `train.folds` — metadata, не доказательство отсутствия утечки из init/mining
  teachers; verifier provenance передаётся отдельно. Test не калибрует масштабы.
- Сохранить допуск C3 ≤0.002 и явно отметить непрошедший пока production-gap gate.

## C5: запуск и замер

- Зафиксировать принятую default модель/состав только после приёмки; historical
  legacy оставить явной альтернативой, не скрытым default.
- Отделить загрузку/сборку (может использовать сеть) от runtime `network_mode:none`.
- Официальный Extractor остаётся открытым вопросом до ответа организаторов;
  не называть собственную сигнатуру полученной от них.
- C5 timer: disk/JPEG, crop/resize, forward, L2. Verifier вне extract-time,
  но внутри полного pipeline wall time. Batch=1 + throughput + VRAM измерять
  на выбранном стеке и указанном оборудовании, не переносить старые коэффициенты.

## C6: формат и кандидаты

- `submission.csv`: **11 колонок без заголовка**, сначала `query_id`, затем
  ровно 10 различных gallery ID в порядке итогового ранжирования. Все query,
  независимо от отказа. Это соответствует действующему валидатору/эталону.
- Junk удаляет только evaluator, **без добора**. Ни helper, ни отчёт не должны
  извлекать замену из полного ranking после junk-фильтра для заявления C6 mAP.
- Удалить устаревшее «двойник никогда не верхний кандидат»: текущие D-023/D-024
  оставляют same-camera совпадение, twins filter выключен; `camera_id` на
  инференсе отсутствует и не используется.
- У принятого query до трёх строк candidates; решает верхняя confidence. Нижние
  ранговые confidence не являются вероятностями. Отказ — отсутствие строк query.
- Shape `(Nq+Ng,D)`, float32; порядок query→gallery доказывается генератором,
  не только проверкой shape. Связать файлы SHA с принятым image/bundle.

## Verifier и confidence: два разных режима

Legacy model-v1: прежний `cosine + w*sigmoid(logit)` и его прежний порог остаются
историческим рецептом. Fusion: hub-corrected scores → **ровно top-10** одного
query → `z(base_top10) + w*z(logits_top10)`; z имеет `ddof=0`, epsilon `1e-9`,
tie-break stable в порядке gallery. При w=0 — порядок базы без вызова verifier.
Утверждение «падение mAP ограничено весом verifier» удалить: оно математически
не следует из коэффициента в score.

Hub считается только по статической gallery: top-3 соседей без диагонали,
стандартизация hub, вес 0.5. Confidence **не равна** смешанному reranking score:
это сырой cosine выбранного после verifier top-1, нормированный mean/std
off-diagonal gallery–gallery (`ddof=0`, epsilon `1e-12`). Никакие другие query
в статистики не входят.

A-103 передаёт w=0.15, threshold=6.3 для своего C4 стека. До подтверждения полного
рабочего пути и выбора 2/3 моделей не превращать эти числа в универсальную
калибровку. Legacy пороги, число 6.0 и новый 6.3 принадлежат разным recipes.

Отдельно переименовать дублирующий заголовок C7 «Таблица скоростей», чтобы ссылки
на контракт verifier и benchmark не были неоднозначными.
