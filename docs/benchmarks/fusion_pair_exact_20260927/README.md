Проверка fallback из D-062/D-064 после прямого A5000-замера B. Состав:

## Решение

Для финальной сдачи выбираем **пару DINO392+CLIP288**:

- `rerank_weight = 0.15`;
- `candidate_threshold = 6.6`;
- all-data verifier остаётся `v_fus_all_frz_input392.pt`, SHA-256
  `aa254e396ac0be78d29f32641e83f8d18e165d76eb3345c18c1054d105b9abf5`.

Пара теряет у тройки всего 0,003816 среднего C4 mAP@10 и 0,002303
CandidateScore. На прямом A5000/R535 замере B она дала 102,674 FPS против
79,59–82,16 FPS у тройки. При одинаковых остальных критериях измеренный
баланс составляет примерно **+3,37 итогового балла в пользу пары**:
+3,568 за скорость, −0,172 за mAP и −0,023 за режим кандидатов.

Это сравнение использует опубликованный двухфолдовый результат тройки A-103;
на fold 1 у него остаётся оговорка `SigLIP full_avg` против финального `top16`.
Для пары этой неоднозначности нет: оба её компонента matched на обоих фолдах.

## Границы

Это matched C4 replay двух train-фолдов, не OOF5 и не закрытый тест. Прямая
скорость измерена B на all-data весах; mAP all-data по построению не существует.
После упаковки пары B должен повторить self-contained Docker/C6/детерминизм,
query-independence и masked-control, а затем заменить канонический `submission/`.
