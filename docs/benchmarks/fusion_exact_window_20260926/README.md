# Exact-window verifier handoff — 26.09.2026

Цель — закрыть блокер трека B из D-060: обучить рабочий all-data verifier,
снять OOF-логиты ровно на production top-10 и прогнать их через общий
postprocessing/C6-код без приближений.

## Итог для интеграции

- all-data verifier: `v_fus_all_frz`, DINOv2 ViT-S/14, input 392,
  замороженный backbone, curriculum, 4000 шагов, plate-band p=0,5, все фолды;
- sha256 checkpoint:
  `aa254e396ac0be78d29f32641e83f8d18e165d76eb3345c18c1054d105b9abf5`;
- `rerank_weight = 0.15`;
- `candidate_threshold = 6.3`;
- состав эмбеддеров остаётся D-062, hub penalty остаётся D-055.

Порог 6,5 дал лучший средний CandScore в конечной сетке, но выбран 6,3:
это середина устойчивой области 6,1–6,5 и она проигрывает точечному максимуму
всего 0,00135. Параметры подобраны только на train folds 0 и 1; test не
использовался.

OOF verifier для fold 0 — прежний `v_frz_4k`, обученный на folds 1–4. Для
fold 1 специально обучен `v_frz_4k_val1` на folds 0,2,3,4:

- sha256 `v_frz_4k_val1/verifier.pt`:
  `290151588f260f7d4f5d6582a6ae58116e8800091ddda5d08ba041453e033f32`;
- финальный train loss 0,5958, время 16,0 мин на RTX 4090;

иметь форму `(N_query, 10)`, правильный fold, уникальные ID и конечный float32.

каждой строке совпадает с окном, которое фактически строит текущий production
код. Он только переставил логиты: 2 из 1138 строк fold 0 и 0 из 1135 строк
fold 1; несовпавший набор был бы отвергнут.

## Границы вывода

Это точная оценка C4 → production postprocessing → C6 на двух train-фолдах.
Она не является OOF5, не доказывает provenance весов автоматически, не
закрывает известный разрыв cache/full-frame FP16 и не заменяет финальный
A5000/Docker прогон трека B. All-data verifier по построению не имеет своей
валидационной метрики; его рецепт подтверждён двумя OOF verifier.
