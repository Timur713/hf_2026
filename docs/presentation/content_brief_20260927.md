Рабочий материал команды DeepTech AI на 27.09.2026. Исходный срез A:
`479ecd7b0a8dcc6add21e86ca87c65546cea3ea5`; обновление B включает реальные
отчёты A5000, C3 и визуального контроля маски от 27.09, ссылки ниже.
Технические результаты self-contained RC сверены со срезом `4772925`.

[handoff](handoff_20260927.md).

Ниже даны готовые смысловые блоки, а не номера слайдов. Их нужно распределить

Не назначать этим блокам номера 7–11 до проверки исходника.

## Титульный блок

**Falcon Vehicle ReID**

Поиск автомобиля по внешнему виду без распознавания номера

DeepTech AI. ЛЦТ 2026, задача №7 «Фалькон Тех»

## Задача и пользователь

**Сопоставление событий с разных камер**

Когда номер не читается, оператору нужен список визуально похожих автомобилей.
Сервис сравнивает кадр с известной галереей и возвращает кандидатов либо отказ.
Оператор проверяет совпадение по исходным событиям.

**Граница решения:** визуальное сходство помогает искать событие, но само по себе
не устанавливает личность водителя и не доказывает нарушение.

Источник для заметок: [ТЗ, актуальность и разделы 1–2](../../MainTechSpec.md).
Экономический эффект и сокращение времени оператора пока не измеряли.

## Пользовательский путь

**От кадра к проверяемому кандидату**

1. Пользователь передаёт полный кадр и прямоугольник автомобиля.
2. Сервис строит признаки и сравнивает их со статической галереей.
3. Верификатор уточняет порядок десяти ближайших кандидатов.
4. Порог определяет, вернуть кандидата или отказаться от сопоставления.
5. Пользователь проверяет кадры и связанные события.

В текущем прототипе этот путь работает пакетно через CSV и Docker. Отдельный
веб-интерфейс и интеграцию с городской информационной системой не заявляем.

Источник для заметок: [README, входы и выходы](../../README.md),
[C5/C6](../contracts.md). Последний шаг описывает пользовательский сценарий,
а не реализованную автоматическую правоприменительную функцию.

## Вход и результат

**Пакетная обработка изображений**

На входе: каталог изображений, query CSV и gallery CSV с BBox.

На выходе:

| Файл | Содержание |
|---|---|
| `submission.csv` | Десять gallery-кандидатов для каждого запроса |
| `embeddings.npy` | Нормированные признаки query и gallery, `float32` |
| `candidates.csv` | Принятые кандидаты с confidence. Отказ означает отсутствие строки |

Размеры наборов берём из входных файлов. Номер и `camera_id` не используются
в модели или при принятии решения на инференсе. Confidence не является
вероятностью совпадения.

Источник для заметок: [ТЗ, разделы 3–6](../../MainTechSpec.md),
[README](../../README.md).

## Архитектура

**Общий декодер и несколько визуальных представлений**

Кадр декодируется один раз. Каждый эмбеддер получает свой кроп и размер входа.
Сервис нормирует и объединяет признаки, ищет top-10 в gallery, затем применяет
парный верификатор и порог отказа.

Исследуемый состав D-062:

| Участник | Вход | Признаки |
|---|---:|---:|
| DINOv2 ViT-B/14 | 392 × 392 | 1536 |
| CLIP ViT-B/16 | 288 × 288 | 1536 |
| SigLIP2 ViT-B/16 | 288 × 288 | 768 |

Суммарная размерность тройки: 3840. Прямой замер A5000 уже выполнен: тройка
даёт около 80–86 FPS, пара DINO392 + CLIP288 даёт 102,67 FPS на проверенном
8-vCPU хосте. Финальный выбор требует сопоставимой оценки качества и порога
пары, а не только сравнения скорости.

Источник для заметок: [конфиги и профиль тройки](../benchmarks/fusion_a10_20260925/README.md),
[прямой A5000-замер](../benchmarks/fusion_a5000_20260927/README.md),
[реализация fusion](../fusion_runtime.md). Для редактируемой схемы использовать
нативные элементы шаблона. Не вставлять схему в виде скриншота.

## Методология и независимость запросов

**Проверка на неизвестных автомобилях**

Train содержит 9556 кадров, 1541 автомобиль и 96 камер. Пять фиксированных
фолдов разделяют автомобили, а не случайные изображения. Около 20% запросов
в каждом фолде не имеют пары в галерее.

Обучение использует разные камеры одного автомобиля, triplet loss и
классификационную функцию потерь. Маскирование снижает доступность номерной зоны.

Архитектура использует один query и статическую gallery. Кодовый аудит не
обнаружил межзапросных статистик или использования номера камеры. Однако
строгая GPU-проверка confidence при изменении размера batch пока не прошла:
численные отличия между одиночным и пакетным путём описаны ниже. Тестовые данные
используются только для технического прогона и проверки формата.

Источники для заметок: [C1/C2](../contracts.md), [данные](../findings.md),
[правила](../../AGENTS.md). Последнюю формулировку обучения сверить с конфигами
именно принятого финального релиза перед экспортом.
Текущее ограничение: [query-independence в RC](../benchmarks/fusion_a5000_20260927/acceptance/README.md).

## Качество исследовательской цепочки

**Верификатор уточняет порядок внутри top-10**

| Строгий C6 replay сохранённых эмбеддингов | Fold 0 | Fold 1 | Среднее |
|---|---:|---:|---:|
| Fusion + gallery hub penalty | 0,86285 | 0,84178 | 0,85231 |
| С verifier, вес 0,15 | 0,86596 | 0,84675 | 0,85636 |

Метрика: mAP@10. Среднее улучшение в этом сравнении: **0,00404**.

**Обязательная оговорка на самом слайде:** два train-фолда, replay сохранённых
эмбеддингов. Это не пятифолдовая оценка и не сквозная метрика финального Docker.
В fold 1 отчёт указывает SigLIP `avg`, тогда как выбранная тройка использует
`top16`. Эквивалентность рецепта пока не подтверждена.

Источник для заметок: [A-103, точное окно](../benchmarks/fusion_exact_window_20260926/README.md)
и raw JSON рядом с отчётом. Если к сдаче есть сопоставимая оценка одного рецепта,
заменить таблицу целиком вместе с оговоркой и ссылкой на новый отчёт.

## Исследовательский кэш и рабочий путь

**Разрыв локализован в подготовке изображения**

| Одни OOF-веса, fold 0, без verifier | Fusion + hub, mAP@10 |
|---|---:|
| Полный кадр, FP16 | 0,858181 |
| Полный кадр, FP32 | 0,858199 |
| Заново собранный JPEG-кэш 512, FP32 | 0,864015 |
| Заново собранный JPEG-кэш 1024, FP32 | 0,859483 |

В этом сравнении FP16 почти не меняет mAP. Кэш 512 отличается от полного FP32
пути на **0,005816**. Различаются сразу уменьшение изображения,
JPEG-перекодирование и координаты кропа, поэтому эффект отдельного resize
не установлен.

**Обязательная оговорка:** диагностика одного train-фолда, а не принятие нового
preprocessing. Старые C4 не воспроизведены точно: новый кэш 512 выше старого
replay на 0,001163. Допуск C3 0,002 пока не закрыт. Любая смена общего
preprocessing требует согласования A+B, повторной оценки качества, порога
полного стека и скорости.

Источник для заметок: [C3 precision/cache](../benchmarks/c3_precision_cache_20260927/README.md).
Не подписывать разрыв как «потеря из-за FP16» или выигрыш уже внедрённого кода.

## Порог отказа

**Отказ для запроса без надёжного совпадения**

Confidence сравнивает сходство выбранного кандидата со шкалой галереи.
Это число в единицах распределения gallery, а не процент уверенности.

В исследовательском handoff A-103 выбран порог **6,3** внутри устойчивой области
6,1–6,5. Критерий выбора: `0,7 × F1 + 0,3 × TNR`. Средний результат двух фолдов
при выбранном пороге: **0,96277**.

Новый all-data verifier с замороженным backbone и входом 392 уже получен и
включён в private release candidate тройки с весом 0,15 и порогом 6,3.
Контрольная сумма checkpoint приведена в handoff. Это не даёт собственной
отложенной метрики all-data весам.

Порог и вес верификатора нужно подтвердить на окончательном составе и рабочем
пути обработки изображений. В частности, 6,3 нельзя автоматически считать
откалиброванным порогом пары. Число 0,96277 относится к официальной трактовке кандидатов,
которая засчитывает ту же машину с той же камеры. Оно не означает 96,3% точности
поиска между разными камерами.

Источник для заметок: [A-103](../benchmarks/fusion_exact_window_20260926/README.md),
[новый verifier и весовой бюджет](../benchmarks/fusion_a5000_20260927/README.md),
[C2, официальный и диагностический режимы](../contracts.md).

## Производительность и воспроизводимость

**Измеряем весь путь извлечения признака**

| A5000, полный C5 | Batch=1, p50 | Лучший throughput |
|---|---:|---:|
| Тройка, 8 CPU threads / 8 workers | 31,457 мс | 82,158 FPS |
| Та же тройка, повтор | 30,583 мс | 79,594 FPS |
| Тройка, 2 CPU threads / 8 workers | 35,804 мс | 85,516 FPS |
| Пара DINO392 + CLIP288, 8 / 8 | 24,884 мс | 102,674 FPS |
| Тройка, готовый self-contained RC, 8 / 8 | 31,599 мс | 81,445 FPS |

Одна RTX A5000 24 ГБ, **8 vCPU**, 45 ГБ RAM, драйвер **535.54.03**, Ubuntu 22.04.
В контейнере PyTorch 2.5.1+cu121. Таймер включает чтение JPEG, декодирование,
crop, preprocessing, forward и L2. Поиск и verifier измеряем отдельно в полном
pipeline. Использованы 50 прогревов, 300 batch=1 замеров, не менее 10 секунд
на каждый batch 1/8/16/32.

**Обязательная оговорка:** GPU и драйвер теперь измерены напрямую, но CPU хоста
отличается от 128 логических CPU стенда организаторов. Числа справочные,
баллы начисляет жюри. Прогноз 112 FPS для тройки не подтвердился. Штраф скорости
плавный, поэтому состав выбираем по совокупности mAP, кандидатов и скорости.

Отдельный однофолдовый C4 replay без verifier: пара + hub даёт 0,861191,
тройка + hub даёт 0,862852. Этого недостаточно, чтобы считать качество полных
стеков равным или объявить окончательный переход на пару.

Новый self-contained RC из исходников `f47f8a7` проверен непосредственно на
R535, без сети и без подключения кода или моделей с хоста. Внутри образа:
397 pytest passed, два пропуска только Git-history fixtures, fusion/verifier
smoke на 50 кадрах пройден. Более поздняя локальная версия прошла 421 тест,
C6 self-test и smoke50. Это разные версии и среды проверки.

Два полных запуска RC с рабочим input392 verifier заняли **132,216 и 132,305 с**.
Все три файла побайтно совпали и прошли C6. Пиковая память полного pipeline:
1791,41 МиБ по Torch allocator, не весь процесс VRAM. Это формат и
воспроизводимость на тех же входах, не оценка качества all-data весов.

Источник для заметок: [A5000 и raw JSON](../benchmarks/fusion_a5000_20260927/README.md),
[self-contained RC](../benchmarks/fusion_a5000_20260927/acceptance/README.md),
[актуальные локальные проверки](../final_delivery_checklist.md).
Не использовать 241 FPS старой одиночной model-v1 как скорость нового ансамбля.

## Строгая проверка независимости query

**Порядок кандидатов совпал, confidence отличается между batch shapes**

На 24 train-query и фиксированной gallery проверили одиночный путь, batch,
обратный порядок и добавление восьми других запросов. Top-10 ID, порядок
candidate ID и решения принять/отказать совпали во всех вариантах.

Между одиночным и пакетным путём confidence отличается у 17 из 24 query,
максимум **0,001421**. Между пакетным путём и reverse/extras после выравнивания
по query ID совпали и confidence, и эмбеддинги, максимальная разница 0.

**Обязательная оговорка:** строгий gate сохраняет `passed=false`. Возможное
объяснение через FP16 batch-shape rounding ещё не изолировано экспериментом.
Одинаковые решения на этой выборке не гарантируют их совпадение рядом с порогом
на всех возможных данных. Поэтому полная приёмка RC пока не объявляется PASS.

Источник для заметок: [отчёт и raw JSON](../benchmarks/fusion_a5000_20260927/acceptance/README.md).
Не скрывать расхождение округлением confidence и не выдавать этот результат
за доказанное использование запрещённых межзапросных статистик.

## Проверенная оптимизация памяти

**Precast уменьшает VRAM, но не решает вопрос скорости**

Экспериментальная предварительная конвертация весов Linear/Conv2d в AMP dtype
дала побайтно одинаковые признаки на 1774 train fold0 входах с batch=32 и
32 равномерно выбранных входах с batch=1. Максимальная абсолютная разница: 0.

Peak allocated VRAM снизился с 1667,7 до 1198,0 МиБ. Скорость осталась в диапазоне
81,43–86,43 FPS, внутри разброса прежних замеров. Опция **выключена по умолчанию**.

**Оговорка:** равенство относится к проверенным данным и среде. Оно не является
оценкой качества all-data на отложенном фолде или доказательством для любых
входов и backend. Это дополнительный инженерный результат, не обязательный
слайд и не ускорение принятого production-пути.

Источник для заметок: [projection-precast experiment](../benchmarks/fusion_a5000_20260927/README.md#projection-precast-experiment-not-enabled-in-production).

## Устойчивость к номерной зоне

**Контроль геометрической заливкой**

| OOF-кандидат, полный train fold 0 | mAP@10 |
|---|---:|
| Исходные кадры | 0,87104 |
| Те же кадры с фиксированной заливкой | 0,86921 |

Падение: 0,00183. Маска применяется до эмбеддеров и верификатора.

**Обязательная оговорка:** визуальная проверка восьми равномерно выбранных
train fold0 запросов уже обнаружила пропуски и неполное покрытие номеров.
На фургоне сбоку маска закрывает дверь, тогда как номер остаётся справа.
На других примерах номер остаётся выше прямоугольника.

Следовательно, небольшое падение mAP под этой маской **не доказывает**
независимость от номерных признаков и соответствие точной заливке жюри.
Следующая проверка требует train-подвыборки с проверенными прямоугольниками
реальных номеров, включая границу размытия, в обоих путях: embedder и verifier.
Долю покрытия по всему датасету на основании восьми примеров не заявляем.

Источник для заметок: [masked-control](../benchmarks/fusion_a10_20260925/README.md),
[визуальная проверка маски](../benchmarks/train_plate_mask_qa_20260927/README.md).
Число 0,87104 относится к конкретному более раннему verifier и одному фолду.
Его нельзя соединять с A-103 в один график прироста без сопоставимого прогона.

## Ошибки и границы применимости

**Массовые модели и смена ракурса остаются трудными случаями**

Одинаковая модель и окраска у машин одного парка затрудняют различение экземпляров.
Смена вида спереди на вид сзади оставляет мало общих деталей. Ночная съёмка
искажает цвет и скрывает небольшие особенности кузова.

Показываем только ошибки из train-фолдов. В спорном случае сервис должен
поддерживать проверку оператором, а не заявлять гарантированное совпадение.

Визуальный материал: [hard_fusion_f0_fleet.jpg](../errors/hard_fusion_f0_fleet.jpg)
или [hard_fusion_f0.jpg](../errors/hard_fusion_f0.jpg). Это исследовательские
иллюстрации, не статистика ошибок финального релиза. Сохранить подписи и контекст
query / ошибочный кандидат / правильный кандидат, не обрезать доказательные части.

Источники для заметок: [разбор запаса fusion](../defense_notes.md#из-чего-состоит-оставшаяся-ошибка-2409-фолд-0-фузия-трёх-моделей),
[описание иллюстраций](../errors/README.md).

## Масштабирование

**Поиск в большой галерее через FAISS**

В задаче используем точный поиск. Для промышленного масштаба проверили
приближённый индекс на синтетической галерее из миллиона векторов.

| Индекс, 1536 измерений | Задержка поиска | Память | Полнота@10 |
|---|---:|---:|---:|
| Точный IndexFlatIP | 421,18 мс | 5859 МиБ | 1,000 |
| IVF-Flat, nprobe=8 | 2,75 мс | 5859 МиБ | 1,000 |
| IVF-SQ8, nprobe=8 | 2,73 мс | 1465 МиБ | 0,980 |

**Обязательная оговорка:** отдельный CPU-эксперимент, 1536-мерные признаки,
синтетическая gallery. Это не скорость обработки миллиона реальных кадров,
не измерение 3840-мерного fusion и не гарантия такой полноты в другом домене.

Следующий шаг внедрения: повторить оценку индекса на реальной галерее заказчика
и финальном эмбеддинге, затем выбрать память и полноту поиска.

Источник для заметок: [ANN-эксперимент и команда воспроизведения](../ann_scale.md).

## Поставка и дальнейшее внедрение

**Офлайн-контейнер и проверяемый релиз**

Поставка включает код обучения и инференса, зафиксированные зависимости,
конфигурации, Docker и README. Веса закрепляем контрольными суммами. Изображения
монтируются только для чтения. Результат формирует код, без ручной правки CSV.

Для тройки создан private RC `fusion-d063-a5000-20260927-rc1`. Dockerfile
закрепляет URL архива и SHA-256 архива/манифеста. Пакет включает новый all-data
verifier input392. Общий размер файлов весов: **1 160 606 944 байта**, меньше
лимита 2 000 000 000 байт. Проверка metadata all-data проходит, но сама по себе
не доказывает историю обучения или качество.

**Статус на момент подготовки:** self-contained RC прошёл офлайн-прогон,
pytest/smoke, C6, весовой gate и повторные побайтно одинаковые запуски.
Общий сценарий завершился с ошибкой на строгом сравнении confidence между
batch shapes, поэтому **вся приёмка не PASS**. Полный архив результатов и логов
сохранён локально и в private RC с проверенными SHA. Канонический `submission/`
не заменён выходами интеграционного кандидата. Публичный доступ и окончательный
выбор тройки вместо пары не заявляются.

План пилота: проверить качество на согласованной отложенной выборке заказчика,
зафиксировать порог и нагрузку, подключить сервис к системе обработки событий.
Клиентов, внедрений и измеренного экономического эффекта пока не заявляем.

## Сценарий скринкаста, 2–3 минуты

1. Показать frozen commit / tag и команду запуска из финального README.
2. Показать каталог входов и BBox CSV, без учётных данных и закрытых ссылок.
3. Запустить окончательный контейнер с отключённой сетью. Если показ ускорен,
   подписать ускорение, а настоящее время взять из полного лога.
4. Показать появление трёх файлов и успешный C6-валидатор.
5. На train-примере показать query и кандидатов, затем пример отказа.
6. Показать отчёт детерминизма и реальные A5000 latency / FPS выбранного состава.
7. Завершить ссылкой на код и ограничения: одинаковые автомобили, смена ракурса,
   необходимость проверки оператором.

Не показывать тестовые изображения для объяснения ошибок или подбора порога.
Не выдавать запись старого образа за прогон финального релиза.
