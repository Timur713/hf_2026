## Итог

**Открывать исходный репозиторий целиком небезопасно:** в достижимой Git-истории
остались реквизиты доступа к стороннему датасету. Текущий HEAD очищен от этой
находки, но удаляющий коммит не удаляет прежние blobs. Кроме того, текущий
GitHub-аккаунт имеет `WRITE`, а не `ADMIN`.

Пользователь выбрал отдельный чистый публичный snapshot без частной истории.
В этом аудите новый репозиторий не создавался, видимость исходного не менялась,
история не переписывалась, assets не публиковались и серверы не запускались.

## 2. Что переносить в чистую поставку

Основа — **tracked tree**, а не копия рабочей папки и не `git clone --mirror`.
Новая история начинается с одного проверенного snapshot-коммита; исходный
private repository остаётся архивом разработки. Не импортировать его refs,
старые коммиты и автоматические source-архивы старых тегов.

Сохранить для работоспособности и проверки:

- `reid/`, `scripts/`, `tests/`, `configs/`, `splits/`, `third_party/official/`;
- `Dockerfile`, `docker-compose.yml`, `Makefile`, `.dockerignore`, `.gitignore`,
  точные requirements/lock-файлы;
- `submission/` с исходными принятыми байтами всех трёх файлов;
- актуальный README, ТЗ, описания алгоритма, публичных источников и ограничений;
- отобранные final-pair quality/provenance/acceptance отчёты, C6/SHA,
  детерминизм и **неизменённые численные FAIL**, без частных окружений;

## 3. Важная правка для публичного зеркала

Одной замены URL в Dockerfile недостаточно. В
`scripts/stage_fusion_release.py` константа `RELEASE_PREFIX` закреплена на
исходном repository owner, а `tests/test_fusion_docker.py` проверяет тот же
owner регулярным выражением. URL нового публичного зеркала сейчас будет
отклонён загрузчиком.

Нужна узкая packaging-правка B: разрешить конкретный новый release prefix,
сохранить проверку HTTPS/GitHub redirect hosts, fixed tag, archive/manifest SHA,
запрет userinfo/query credential URL и строгую USTAR-установку. Добавить позитивный
тест зеркала и негативный тест постороннего repo. Это не повод ослаблять проверку
до произвольного URL. Веса, preprocessing, порог и reranking не менять.

Публичный архив должен быть побайтной копией принятого bundle:

```text
fusion-pair-d065-bundle.tar.gz
sha256 9eeb99fae8bdcb228265ee83ac51da60da9896199d4746d843b30f3976fa49a8
manifest sha256 4e3eacd2431ae634369b8e34689cb48d579f034207d1fd72bdff29661ad71e22
```

Встроенные provenance URL старого private источника можно честно обозначить как
историю происхождения; они не должны оставаться единственным способом получить
сдаваемые байты. Опубликованный verified bundle — анонимный источник финальных
weights/configs; исходные pretrained URL уже публичны и закреплены revision/SHA.

три файла, `--network none`, fixed weights, реальные A5000/A10 цифры и пределы

Перед публичным freeze:

- заменить clone/archive/release ссылки на проверенное публичное место;
- убрать из основного quickstart ожидание открытия и обязательность `gh`;
- явно создать output directory перед bind mount;
- добавить короткую отдельную команду проверки C6 для трёх полученных файлов;
- сделать переход из README к скринкасту и актуальной презентации;
- проверить локальные Markdown-ссылки после отбора/редактирования docs;
- не обещать anonymous `--target legacy`, если его старые assets не зеркалятся;
- не называть только `make check` доказательством реального smoke: без weights
  developer smoke может SKIP; в приёмке нужен `make smoke-strict`;
- не обещать готовый registry image: опубликованного pullable image нет;
- записать final source commit, новый image ID/digest после URL-правок,
  тот же manifest/archive SHA и SHA трёх канонических выходов;
- отметить, что официальный `extractor.py` отсутствует, а C5 пока предварителен.

Отдельного `LICENSE` в tracked tree не обнаружено. Публичность кода сама по себе
не задаёт разрешение на его коммерческое использование; выбирать новую лицензию
за соавторов нельзя. Это не блокирует чтение/запуск для оценки по правилам
конкурса, но не стоит заявлять несуществующую open-source лицензию.
